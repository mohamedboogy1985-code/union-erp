# البرنامج المحاسبي الكامل + الوحدات الجديدة — خطوات التثبيت والتشغيل

> `Union-ERP` — مشروعك + ثلاث وحدات مضافة (النظام الأساسي • اللائحة المالية • النواة المحاسبية)
> هذه الحزمة **كاملة المصدر**: كل ملفات البرنامج + الملفات الجديدة.
> الحزمة **خالية من `node_modules` و`.env`** — يُنشَأ الأول بالتثبيت، والثاني يبقى عندك ولا يُشارَك.

---

## 1) ما في الحزمة

| المسار | المحتوى |
|---|---|
| `server/` | خادم البرنامج وخدماته ومسارات الـAPI (+ وحداتنا الثلاث) |
| `server/data/` | ملفات البيانات وCSV الرسمية + قواعد النظام الأساسي واللائحة ودليل الحسابات الموحّد |
| `src/` | واجهة البرنامج (React) + الأنواع ومحاكيات الوحدة الجديدة |
| `assets/` | `statutory-app.html` = صفحة الوحدة الجديدة (تعمل بلا إنترنت) |
| `test/` | اختبارات المشروع الأصلية (محدَّثة لتطابق القيم الرسمية المصحّحة) |
| `scripts/` | سكربتا التحقق: `verify-statutory-integration.ts` و`live-integration-check.mjs` |
| `dist/` | **نسخة الواجهة مبنية مسبقاً** — لِتشغيل بلا خطوة بناء |
| `scripts/free-port.mjs` | تحرير منفذ 3000/24678 من أي نسخة قديمة قبل التشغيل (يعمل على Windows/Linux/macOS) |
| `دمج/` | الـpatch + دليل الدمج الكامل + لقطات الوحدة داخل برنامجك |
| `run.cmd` / `run.ps1` | تشغيل بضغطة واحدة (تثبيت تلقائي عند أول مرة) |
| `run-prod.cmd` | تشغيل نسخة الإنتاج الجاهزة (بلا بناء) |
| `verify.ps1` | تحقق شامل من التثبيت (3 فحوص) |

## 3) التثبيت (خمس خطوات)

1. فُكّ ضغط الحزمة في مسار قصير بلا مسافات، مثل `D:\union-erp`.
2. افتح `PowerShell` داخل المجلد (Shift + زر الفأرة الأيمن → Open PowerShell here).
3. ثبّت الحزم:
   ```powershell
   npm install
   ```
   (يستغرق دقائق في أول مرة، وينشئ مجلد `node_modules`.)
4. تأكد أن المنفذ 3000 غير مستخدم، أو اختر منفذاً آخر.
5. شغّل البرنامج — §4.

> يبدأ PostgreSQL المضمّن الدائم تلقائياً افتراضياً، ويستمع محلياً على `127.0.0.1`. تحقق من `/api/health`: يجب أن تكون `database.connected=true`. إذا ظهر تحذير بدء PostgreSQL أو كانت الحالة «ذاكرة داخلية»، فقاعدة SQL غير متصلة ولا تُعدّ البيانات محفوظة بين مرات التشغيل؛ أصلح إعداد البيئة أو اربط قاعدة خارجية عبر `DATABASE_URL` أو `SQL_HOST`.

## 4) التشغيل

### الطريقة الأولى (الأسهل) — ضغطة واحدة

```powershell
.\run.cmd
```
ماذا يفعل؟ يفحص Node → يثبّت الحزم إن لم تكن مثبَّتة → يشغّل الخادم → يفتح المتصفح.
لتغيير المنفذ: `.\run.cmd -Port 4300` — ولإيقاف الخادم: `Ctrl + C`.

### الطريقة الثانية — الأوامر المباشرة

```powershell
npm run dev
```

### نسخة الإنتاج بلا بناء (الواجهة مبنية في الحزمة)

```powershell
.\run-prod.cmd
```
(أو يدوياً: `$env:NODE_ENV="production"; npx tsx server.ts`)
نسخة الإنتاج أسرع في التحميل، ولا تحتاج `vite`.

### الوحدة داخل التطبيق (لا واجهة منفصلة)

**١) شاشة «الرقابة المالية والموازنات»** — من نفس بند الرقابة في الشريط الجانبي، صارت تضم ثلاثة تبويبات:

| التبويب | المحتوى |
|---|---|
| اللائحة المالية والرقابة | شاشة برنامجك الأصلية كما هي |
| **لائحة النظام الأساسي (69 مادة)** | **لوحة النظام الأساسي كاملة: 69 مادة قابلة للبحث + نص كل مادة وقواعدها + خطة التفعيل + التغطية بالأبواب + البنود المفتوحة** |
| الموازنة التقديرية | شاشة برنامجك الأصلية كما هي |

**٢) شاشة «النظام الأساسي والوحدات»** — بند منفصل يضم:

| التبويب | المحتوى |
|---|---|
| اللائحة المالية | 90 قاعدة (مانعة/تحذير/تدقيق) + 53 عتبة + تغطية الأبواب |
| النواة المحاسبية | 118 حساباً + الأقسام والحسابات المساعدة + ميزان المراجعة + الأطراف التحليلية + سلسلة SHA-256 |
| الفحص والحكامة | إدخال قيد أو إجراء حكامة واختيار المرحلة (SHADOW/AUDIT/WARN/ENFORCE) ورؤية المخالفة والمادة والعلاج |

> صفحة `/statutory` المستقلة باقية كأداة إضافية، لكن الاستخدام اليومي من داخل البرنامج نفسه.

### قرارات دليل الحسابات الثلاثة (محسومة)
نُفِّذت داخل البرنامج، وتراها في **النظام الأساسي والوحدات ← النواة المحاسبية** أعلى الجدول:

| القرار | ما نُفِّذ | الأثر في التشغيل |
|---|---|---|
| `COA-ANOM-DUP-1111` | **اعتماد الدمج**: أُسقط الصف المكرر (الكود القديم 100) وبقي حساب واحد على الكود **1111** | الأكواد الفريدة **118**، والترحيل على 1111 صار مقبولاً |
| `COA-OPEN-001` | **إضافة الحساب 1211 «النقدية بالخزينة»** في قسم 1200 وإعلانه حساباً نقدياً مع 1101 | قواعد **م9** (سقف الصرف النقدي 25,000) و**م6** (السلفة المستديمة) تُقاس **آلياً** من أسطر القيد — بلا تمرير يدوي للتصنيف |
| `COA-OPEN-002` | **الدليل النشط = دليل البرنامج** (1101 الخزينة • 1301 مدينون متنوعون)، والدليل الموحد مرجع التصنيف التفصيلي، مع **معيّن معتمد** بينهما | لا أرصدة مزدوجة: 1101↔1211 و1301↔1101 معتمدان، و5 مرشّحين و8 بلا مقابل معلَّقون في `COA-OPEN-003` |

> إن أراد البرنامج لاحقاً العمل بأكواد الدليل الموحد (118): يكفي تغيير إعلان حسابات النقد والمدينين في `server/data/account-guide-mapping.ts` — بلا لمس دليل البرنامج النشط.

### تشغيل اختبارات البرنامج نفسه
```powershell
npm run test
```
يُشغّل محركات البرنامج الأصلية: المحاسبة (8) • التحسينات (14) • شؤون العاملين • محرك اللائحة • الحضور (7) • حذف القيود 2024. كلها تنجح. وملفا اختبار واجهة (`jules-ui` و`operator-assistant-ui`) يعملان **jsdom 30** الذي يحتاج Node 22.10 أو أحدث — أنت على Node 24.18 فتنجح عندك، وعلى Node 20 تفشل برسالة `webidl.util.markAsUncloneable is not a function` وهي مسألة بيئية لا علاقة لها بالوحدات المدمجة.

### إذا ظهر `EADDRINUSE: address already in use 0.0.0.0:3000`
معناها نسخة أخرى من البرنامج تعمل بالفعل على المنفذ 3000 (وربما ترى أيضاً `Port 24678 is already in use` وهو منفذ التحديث اللحظي لنفس النسخة). الرسالة **ليست خطأ من الوحدة الجديدة** — الخادم يكون قد حمّل كل شيء بنجاح قبلها. اختر أحد الحلّين:

**الحل 1 — تحرير المنفذ ثم التشغيل (الأسرع):**
```powershell
npm run dev:clean
```
هذا الأمر يشغّل `scripts/free-port.mjs` فيُغلق أي عملية قديمة تشغل 3000 أو 24678، ثم يبدأ التشغيل. (يعمل من PowerShell وcmd وGit Bash.)

**الحل 2 — تشغيل على منفذ آخر:**
```powershell
npm run free-port
$env:PORT=3001; npm run dev
```
ثم افتح `http://localhost:3001`.

**أو من Git Bash / MINGW64 (كما شغّلت سابقاً):**
```bash
netstat -ano | grep :3000        # لاحظ رقم الـ PID في آخر السطر
taskkill //F //PID 12345         # استبدل 12345 بالرقم (لاحظ الشرطتين المزدوجتين)
npm run dev
```

> يمكنك أيضاً استخدام `RUN_UNION_ERP_WINDOWS.cmd` الجاهز: يحُرّر المنفذين ثم يشغّل البرنامج ويفتح المتصفح.

## 5) مرحلة الإنفاذ (مهم أول مرة)

البرنامج يبدأ في مرحلة **`SHADOW`**: يرصد المخالفة ويسجّلها **ولا يمنع أي قيد** — لا يعطّل عملك اليومي.

| المرحلة | السلوك |
|---|---|
| `SHADOW` | رصد وتسجيل فقط (الافتراضي) |
| `AUDIT` | رصد + تدقيق |
| `WARN` | رصد + تحذير |
| `ENFORCE` | **منع** القيود المخالفة مع   يان المادة والعلاج |

لتفعيل الإنفاذ الكامل:

```powershell
$env:STATUTE_ENFORCEMENT_STAGE = "ENFORCE"
npm run dev
```

ويمكن الفحص لطلب واحد بلا تغيير الإعداد العام: `/api/financial/check?stage=ENFORCE`.

## 7) حل المشكلات

| العَرَض | الحل |
|---|---|
| `running scripts is disabled` عند `run.ps1` | استخدم `.\run.cmd` أو `powershell -ExecutionPolicy Bypass -File run.ps1` |
| المنفذ مستخدم | `.\run.cmd -Port 4300` |
| الدليل يظهر **0 حساب** والقيود فارغة | سببه محمّل CSV يختار ملف التدريب بدل الرسمي — **مُصلَح في هذه الحزمة** (`server/services/csv-import.service.ts`). بعد الإصلاح: 117 حساباً + 3,083 قيداً |
| «تعذّر تشغيل PostgreSQL المضمّن» أو `database.connected=false` | ليست حالة SQL ناجحة: افحص سجل الإقلاع ومجلد `pgdata`، أو اضبط اتصالاً خارجياً عبر `DATABASE_URL` أو `SQL_HOST/SQL_USER/SQL_PASSWORD/SQL_DB_NAME`، ثم أعد فحص `/api/health` |
| خطأ `Cannot find package 'vite'` | ناقص `npm install` (أو استخدم `run-prod.cmd` الذي لا يحتاج vite) |
| `npm install` يتوقف عند تنزيل Electron | انتظر أو نفّذ `npm install --ignore-scripts` ثم `npm run dev` |
| اختباران يفشلان (`jules-ui` / `operator-assistant-ui`) | خطأ بيئي في `jsdom`+`undici` يظهر في النسخة الأصلية أيضاً ولا علاقة له بالوحدات |
| أريد إيقاف الوحدة الجديدة | لا تحذف شيئاً: هي مسارات مستقلة، ودرجة `SHADOW` تكفي. للتعطيل التام أزل كتلة `createStatuteRouter...` من `server.ts` |

## 9) بيانات مهمة

* بيانات البرنامج تُحمَّل من ملفات `server/data/` (الدليل الموحّد + دفاتر اليومية التاريخية) — لا تُحذف.
* لا يوجد `.env` في الحزمة عمداً؛ أنشئه من `.env.example` إن احتجت قاعدة بيانات أو مزوّد ذكاء اصطناعي.
* التشغيل بلا `.env` = وضع محلي بالذاكرة (بيانات الجلسة لا تُحفَظ بعد الإغلاق).
* لتركيب الوحدات نفسها على مستودعك المرفوع: راجع `دمج/` (الـpatch محدَّث لالتزام `3869ba1`).
