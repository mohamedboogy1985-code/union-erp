# محاسبك — مساعد تشغيل ERP بالصوت والفيديو

## ما الذي نُفّذ؟

مساعد عائم واحد داخل `Layout`، متاح من زر **«محاسبك»** في كل صفحات البرنامج، ومن صفحة **المساعد الحي** داخل بوابة الذكاء الاصطناعي. لا يُفكّ المكوّن عند التنقل داخل الكيان نفسه. **هذا مساعد تشغيل للبيانات والنماذج، وليس Jules الذي يعدّل كود المستودع.**

حسب الاختيارات المتفق عليها:

- **إملاء إلى مسودات بيانات، وليس أرشيف تسجيلات:** مقطع صوتي قصير → تفريغ وفهم → مسودة حقول قابلة للتعديل → مراجعة وتعبئة → حفظ يدوي من النموذج الأصلي.
- **شخصية بشرية واقعية:** ربط WebRTC بـ D-ID Agents Streams، باستخدام Agent من نوع V2 أو V3، بعد تهيئة حساب الخدمة.
- **المتصفح وWindows:** واجهة مشتركة، والتقاط صوت قياسي عبر Web Audio، دون الاعتماد على `SpeechRecognition` الذي لا يتوفر دائماً في Electron.

لا توجد صورة أو محادثة مزوّرة تدّعي اتصالاً فعلياً. بدون المفاتيح الصحيحة تظهر لوحة إعداد صريحة، ولا يُرسل أي صوت أو طلب فيديو إلى مزوّد خارجي.

## القدرات والحدود الفعلية

### التنقل

المساعد يقترح شاشة من سجل شاشات البرنامج الفعلي. بعد مراجعة الانتقال والضغط على الزر، تُفتح الشاشة والبوابة المناسبة. المستخدم يستطيع الوصول فقط للشاشات والكيانات المصرّح بها لحسابه. شاشتا الإعدادات وJules للمدير فقط.

الانتقال إلى **حساب أو كيان آخر** يغلق الوسائط ويمسح المحادثة والمسودة والتقرير المعروض. لا تُنقل بيانات الكيان السابق إلى طلبات الكيان الجديد. احتفظ بأي نموذج غير محفوظ قبل الانتقال.

### إدخال البيانات

المساعد لا يتحكم في DOM بصورة عامة ولا ينفّذ JavaScript من النموذج. يتعامل فقط مع حقول نماذج المراجعة المسجّلة بالخاصية `data-assistant-draft`:

- إنشاء القيود، والتحصيل، والأعضاء، والحسابات، والجهات المساعدة.
- إعداد الفاتورة الإلكترونية يدوياً.
- تسجيل الشئون الإدارية للعاملين والسلف وسدادها.
- تسجيل الحضور وتعديل الحركة وإثبات الغياب.
- إعداد مسير المرتبات.

حقول النص والرقم والتاريخ والوقت والقوائم في هذه النماذج مدعومة؛ النماذج التي ليس لديها إدخال يدوي أصلاً لا تُنشأ لها عمليات جديدة بالذكاء الاصطناعي. لا تتضمن هذه النسخة كتابة عامة في كل جدول أو التحكم بكل زر.

**مستبعدة:** كلمات المرور، مفاتيح الخدمات، OTP، الحقول المخفية والمعطّلة، رفع الملفات، صناديق الاختيار/الراديو، نماذج الدمج والاستيراد غير المسجلة وأزرار الاعتماد والحذف والترحيل. الحد 40 حقلاً للطلب؛ قسّم النماذج الكبيرة إلى طلبات واضحة.

1. افتح نموذج الإضافة/التعديل من الشاشة المعتادة.
2. اضغط «اكتشاف الحقول» للتأكد من تسمياتها.
3. قل مثلاً: «اكتب في البيان اشتراك سنوي، وفي المبلغ 500 جنيه».
4. اقرأ التفريغ والقيم، وصحّح أي قيمة داخل المسودة.
5. فعّل مربع المراجعة واضغط «تعبئة الحقول بعد المراجعة».
6. **احفظ من زر النموذج الأصلي.** المساعد لا يضغط هذا الزر نيابة عنك.

لا تُرسل القيم الحالية للحقول إلى Google؛ تُرسل التسميات والأنواع فقط مع نص/صوت المستخدم وسياق محادثة قصير. اختيار قيمة من قائمة HTML يتطلب تطابقاً وحيداً مع القيمة أو الاسم أو كود الحساب الرقمي الواضح؛ لا تُرفع قائمة الأسماء كاملة إلى النموذج لتخمين الاختيار. القوائم المركبة التي تتطلب نداء اختيار هوية مستقل (`onSelect`) تُختار يدوياً حتى لا تتحول كتابة الاسم إلى اختيار خاطئ.

إذا تغير الحقل أو الشاشة أثناء إعداد المسودة، يُرفض استبدال قيمك القديمة. تحديث الحقول يستخدم أحداث React مع تفريغ التحديثات بين الحقول لمنع ضياع القيم في النماذج التي تعتمد حالة كائن واحد. بعض الاختيارات قد تغير تركيب النموذج؛ عندها يُطلب مراجعة ما عُبّئ وإكمال البقية يدوياً، دون أي حفظ.

### استخراج التقارير

تُقرأ البيانات وتُحسب التقارير داخل خادم ERP، لا من ذاكرة النموذج:

1. ميزان المراجعة.
2. الإيرادات والمصروفات.
3. الأستاذ العام.
4. المقبوضات والمدفوعات.
5. سجل التحصيل.
6. القيود المحاسبية.
7. الجهات والأستاذ المساعد.
8. دليل الأعضاء بحسب كيان اللجنة.
9. دليل العاملين، المقيّد بكيان مركز التدريب؛ بيانات العاملين القديمة لا تحتوي معرف كيان لكل صف.

يمكن اختيار الفترة والبحث. المعاينة تعرض أول 100 صف والتصدير حتى 1000 صف وفق المرشحات؛ قسّم التقارير الأكبر بالتاريخ/البحث. ملف التصدير **CSV UTF-8 مع BOM** قابل للفتح في Excel، وليس ملف XLSX أو PDF. يطبق حماية خلايا الصيغ. التصدير يحتاج صلاحية `print:all` ويعيد قراءة التقرير بالمرشحات نفسها.

لا تُرسل صفوف التقارير إلى Google أو D-ID. عند تفعيل الصوت، قد يُرسل **الرد المختصر** إلى D-ID؛ مثلاً اسم التقرير وعدد صفوفه. أي معالجة للأرصدة تتبع الخدمات المحاسبية الحالية ودورة القيود والكاش الموجود في ERP.

## الخصوصية وإيقاف الوسائط

- لا يبدأ الميكروفون عند فتح الصفحة أو دخول حسابك؛ يلزم زر بدء واضح وموافقة معالجة البيانات.
- تظهر علامة تسجيل وعدّاد وزر إيقاف/إلغاء، حتى عند تصغير لوحة المساعد.
- الحد **45 ثانية للمقطع**. الإيقاف يرسل المقطع للفهم؛ الإلغاء يحذفه دون إرسال.
- يُلتقط صوت أحادي ويحوّل إلى WAV PCM 16kHz داخل الذاكرة. لا إنشاء لملفات تسجيل على القرص.
- إغلاق اللوحة، تغيير المستخدم/الكيان، مغادرة التبويب أو إيقاف الجلسة يوقف مسارات الميكروفون والفيديو.
- لا تُفتح كاميرا المستخدم؛ اتصال أفاتار D-ID يستقبل صوتاً وفيديو فقط ولا ينشر مسار ميكروفون/كاميرا المستخدم إليه.
- لا تُحفظ المحادثة أو الصوت في `localStorage` أو طابور العمل دون اتصال أو قاعدة ERP. آخر 8 رسائل مختصرة فقط قد تُرسل كسياق في الجلسة الحالية.
- يحتفظ الخادم بردود قصيرة في الذاكرة حتى 5 دقائق لتشغيل الصوت المرتبط بالمستخدم والكيان. هذه ليست أرشيفاً دائماً. «إيقاف ومسح» يطلب حذفها وإغلاق الوسائط.
- بيانات النموذج التي تحفظها بنفسك تتبع التخزين والمزامنة المعتادين للبرنامج.
- لا تُملي كلمات مرور أو أسراراً. أخبر المشاركين قبل التسجيل، وراجع سياسات المؤسسة قبل إرسال بيانات شخصية أو مالية إلى مزوّد خارجي.
- **عدم الاحتفاظ المحلي لا يعني انعدام الاحتفاظ عند Google أو D-ID.** راجع شروطهما وإعدادات الخصوصية والحصص. لا يستطيع البرنامج استرجاع بيانات سبق إرسالها إلى مزوّد.

## الإعداد على الخادم

### الطريقة الأسهل: أمر تفاعلي واحد

من **نسخة المشروع المصدرية على الجهاز/الخادم الذي سيشغّل ERP**، افتح طرفية تفاعلية وشغّل:

```bash
npm run assistant:setup
```

الأداة تسألك عن موافقة الخصوصية والحصص، ثم مفتاح Gemini، وهل تريد الفيديو، ومفتاح D-ID ومعرّف Agent عند اختياره، وكلمة مرور مدير ERP. المفاتيح وكلمة المرور **لا تظهر أثناء الكتابة ولا تُمرر عبر سطر الأوامر**. لا ترسلها في المحادثة.

- لا تُنشئ الأداة حسابات خدمات أو مفاتيح Google/D-ID؛ أحضر مفاتيح حساباتك أولاً.
- تتحقق محلياً من صيغة الإعدادات، وتحوّل كلمة مرور ERP إلى bcrypt، ثم تطلب تأكيد الحفظ.
- تُنشئ مفتاح تشفير عشوائياً عند غيابه، وسر JWT إذا كان مفقوداً أو ضعيفاً، بعد التنبيه والتأكيد. تحافظ على الأسرار الحالية القوية وإعدادات قاعدة البيانات وJules.
- لا تدوّر مفتاح تشفير موجوداً ضعيفاً تلقائياً، حتى لا تفقد الوصول إلى بيانات مشفّرة سابقة. راجع خطة التدوير أولاً. إذا كان المفتاح غائباً مع وجود بيانات مشفّرة قديمة فاستعد مفتاحها الأصلي قبل الإعداد.
- تكتب `.env` باستبدال ذري وملف مؤقت مستثنى من Git، دون نسخة احتياطية نصية للأسرار. ترفض الملف الرمزي أو تغيّر الملف أثناء الإجابة.
- تضبط أذونات `0600` حيث يدعمها النظام؛ على Windows احمِ المجلد بأذونات NTFS المناسبة أيضاً.
- لا تتصل الأداة بالمزوّدين ولا تعيد تشغيل الخادم أو تنفق حصة الخدمة. بعد الحفظ أوقف التشغيل القديم وأعد تشغيله، ثم اختبر الدخول والمساعد.
- متغيرات بيئة التشغيل تتقدم على `.env`. إذا كان تشغيل المعاينة يفرض `DEMO_MODE=true` أو يعطّل المساعد، يجب إعادة تشغيلها دون هذه التجاوزات. الأسرار المقدّمة من مدير أسرار خارجي تبقى معتمدة عليه ولا تُستبدل بأسرار مختلفة لمجرد غيابها من الملف.

لفحص الجاهزية **دون عرض قيم الأسرار أو تغيير الملفات أو اتصال خارجي**:

```bash
npm run assistant:check
```

`localConfigurationReady` و`videoConfigurationReady` تقيسان الإعداد المحلي فقط. `providerConnectionTested` يبقى `false`؛ صحة الحساب والمفتاح ونوع Agent تُختبر عند تشغيل الجلسة الفعلية.

إذا كنت تملك EXE فقط، نفّذ إعداد الخدمات على الخادم المركزي/نسخة المصدر، وليس داخل حزمة Windows الموزعة. باقي هذا الدليل يشرح الإعداد اليدوي عند الحاجة.

### 1. الدخول الحقيقي إلى ERP

نفس منظومة JWT المستخدمة في لوحة Jules، لكن المساعد الجديد متاح أيضاً لغير المدير ضمن صلاحياتهم:

```dotenv
DEMO_MODE=false
JWT_SECRET=<strong-random-secret>
ENCRYPTION_KEY=<another-strong-random-secret>
ERP_ADMIN_USER_ID=usr-mohamed-abdallah
ERP_ADMIN_PASSWORD_HASH='<bcrypt-hash>'
```

لا تستبدل أسراراً صحيحة بالأمثلة. لإنشاء بصمة كلمة مرور من طرفية تفاعلية محلية:

```bash
npm run auth:hash-password
```

اسم دخول المدير الحالي `mohamed.abdallah`. إذا كان TOTP مفعّلاً، تُطلب كلمة المرور والرمز معاً. التوكن في ذاكرة الواجهة فقط ويُمسح عند تغيير الحساب. توكنات وضع العرض لا تفتح المساعد بعد التحويل للوضع الصارم.

لتهيئة مستخدمين فعليين آخرين موجودين، يوجد متغير اختياري **على الخادم فقط**:

```dotenv
ERP_USER_PASSWORD_HASHES='{"existing-user-id":"<bcrypt-hash>"}'
```

هذا لا يُنشئ مستخدمين ولا يغيّر أدوارهم. البصمات بتكلفة 10–16، ويمكن توليدها بالأداة نفسها وأخذ قيمة البصمة. لا تضع كلمات مرور صريحة في JSON، ولا ترسل البصمات في المحادثات أو Git.

### 2. Gemini للإملاء والفهم

احصل على مفتاح من حساب Google AI Studio، واضبطه في المتغير المخصص:

```dotenv
AI_ASSISTANT_ENABLED=true
AI_ASSISTANT_GEMINI_API_KEY=<server-only-gemini-key>
AI_ASSISTANT_MODEL=gemini-3.7-flash
```

الموديل الافتراضي يطابق اختيار المشروع الحالي؛ اضبط نموذج Gemini متاحاً في حسابك يدعم الصوت وJSON إذا تغير التوافر. **مفتاح Jules لا يعمل هنا.** لا يستخدم هذا المساعد مفتاح `GEMINI_API_KEY` القديم ضمنياً، حتى لا يفعّل واجهات الذكاء الاصطناعي القديمة بالخطأ.

أعد تشغيل الخادم، افتح «محاسبك»، وسجّل دخول ERP، ثم وافق على معالجة الإملاء والنص. يمكن استخدام اختصارات التقارير المحلية بدون مفتاح Gemini بعد تفعيل الوحدة والدخول الآمن.

### 3. الشخصية البشرية الواقعية عبر D-ID

1. سجّل الدخول إلى D-ID Studio بحسابك.
2. أنشئ Agent من نوع **V2 Photo أو V3 Pro/Clip**، واختر شخصية مرخّصة أو صورة تملك موافقة صاحبها، وصوتاً عربياً مناسباً.
3. احتفظ بمعرّف Agent.
4. أنشئ مفتاح API من إعدادات حساب D-ID؛ احفظ قيمته كما يوفرها المزوّد على الخادم.
5. اضبط:

```dotenv
DID_AVATAR_ENABLED=true
DID_API_KEY=<server-only-d-id-api-key>
DID_AGENT_ID=<your-agent-id>
```

6. أعد تشغيل الخادم. داخل اللوحة، وافق على إرسال الرد المختصر وتكلفة الفيديو، ثم اضغط «تشغيل الفيديو الواقعي».

يستخدم التكامل `/agents/{agentId}/streams` مع تبادل SDP/ICE عبر خادمك. مفتاح D-ID ومعرّف جلسته الداخلي لا يصلان إلى المتصفح؛ يحصل المتصفح على معلومات WebRTC وبيانات TURN مؤقتة لازمة للوسائط. الوسائط نفسها تتصل عبر TURN/WebRTC من متصفح المستخدم، لذلك يجب أن تسمح الشبكة بذلك.

**هذه النسخة لا تستخدم مسارات `talks/streams` القديمة، ولا تدعم V4/LiveKit أو مزوّد فيديو آخر تلقائياً.** دعم ذلك يحتاج موصّلاً إضافياً. اختيار V2/V3 يمنح فيديو واقعياً فعلياً، وليس صورة ثابتة تتحرك اصطناعياً في الواجهة.

الجلسة محدودة محلياً بعشر دقائق، وقد تنتهي مبكراً بسبب خمول/حصة المزوّد. هناك اتصال فيديو واحد لكل مستخدم وكيان في عملية الخادم. لا توجد إعادة اتصال أو إعادة إرسال مدفوعة تلقائياً. إغلاق الاتصال أثناء تهيئته يطلب إغلاقه أيضاً إذا اكتملت التهيئة لاحقاً. الإغلاق لدى المزوّد أفضل جهد عند انقطاع الشبكة؛ راجع حساب الخدمة والحصة عند فشل الاتصال.

بدون فيديو، يوجد رد صوتي بديل باستخدام **صوت عربي محلي مثبت** في النظام/المتصفح. إذا لم يوجد صوت عربي محلي تُعرض رسالة واضحة، ولا ندّعي أن الصوت يعمل. لا يُشغّل الصوت المحلي والفيديو معاً للرد نفسه.

## المتصفح وWindows

### المتصفح

استخدم متصفحاً حديثاً وHTTPS في التشغيل عن بُعد. اسمح بالميكروفون عندما تطلبه. المعاينة المضمّنة قد تمنع الميكروفون إذا لم يسمح إطار الاستضافة بذلك؛ افتح المعاينة في تبويب مستقل حينها. الكتابة والتقارير لا تحتاج الميكروفون.

### Electron على Windows

- نفس واجهة المساعد ومسارات HTTP النسبية والتقاط WAV؛ لا اعتماد على خدمة Chrome Speech Recognition.
- نافذة أذونات صريحة قبل منح الميكروفون/الكاميرا، ومن أصل البرنامج فقط.
- `nodeIntegration=false` و`contextIsolation=true` و`sandbox=true` تبقى كما هي.
- الروابط الخارجية لا تفتح بروتوكولات `javascript:` أو `file:`، والمقارنة مع أصل التطبيق كاملة وليست بادئة نصية.
- لا توزّع مفاتيح Gemini/D-ID أو أسرار JWT داخل EXE أو حزمة موارد قابلة للاستخراج.

لنسخ Windows المرتبطة بخادم مركزي، اضبط **في بيئة تشغيل Electron**:

```dotenv
ERP_SERVER_URL=https://erp.your-organization.example
```

يجب أن يكون أصلاً HTTPS بلا مسار فرعي أو بيانات دخول أو query. عند ضبطه لا يُشغّل Electron خادماً محلياً بديلاً عند تعذّر الشبكة؛ يعرض خطأً واضحاً بدلاً من نقل المستخدم إلى قاعدة بيانات مختلفة. بدون هذا المتغير يحتفظ التطبيق بتشغيل الخادم المحلي السابق.

أدوات البناء المعتادة لم تتغير:

```bash
npm run build
npm run build:server
# على بيئة بناء Windows المجهزة:
npm run electron:build
```

## API والأمان

كل نقاط `/api/operator-assistant/*` عدا `/status` تتطلب JWT حقيقياً، حساباً نشطاً غير تجريبي، وضع أمان صارماً وصلاحية الكيان. `x-user-id` ليس إثبات دخول.

| الطريقة | المسار | الاستخدام |
|---|---|---|
| GET | `/status` | جاهزية محلية غير سرية، لا يتصل بالمزوّدين |
| POST | `/turn` | نص **أو** WAV مع `consent:true` وتسميات حقول وسياق محدود |
| POST | `/report` | تقرير محلي؛ `download:true` لتصدير CSV |
| POST | `/avatar` | إنشاء اتصال فيديو بعد موافقة منفصلة ومعرّف طلب عشوائي |
| POST | `/avatar/:id/sdp` | إجابة SDP لاتصال يملكه المستخدم |
| POST | `/avatar/:id/ice` | بيانات شبكة للاتصال نفسه |
| POST | `/avatar/:id/speak` | نطق `replyId` قصير يملكه المستخدم/الكيان، وليس نصاً حراً مجهول المصدر |
| DELETE | `/avatar/:id` | إغلاق اتصال محدد |
| DELETE | `/avatar` | إلغاء إعداد اتصال معلّق بمعرّف طلبه |
| POST | `/forget` | مسح الردود المؤقتة وإنهاء الوسائط للمستخدم والكيان |

- لا توجد أداة SQL أو shell أو طلب URL حر أو كتابة ERP أو اعتماد مالي داخل مخرجات النموذج.
- حد نص 6000 حرف، صوت 45 ثانية / 1.5 MB، جسم HTTP حتى 3 MB، ورد مزوّد حتى 2 MiB، ومهلة 25 ثانية.
- 12 طلب فهم و12 طلب نطق في الدقيقة، و3 عمليات إنشاء فيديو، و30 طلب تقرير، و120 إشارة اتصال لكل مستخدم. لا استثناء للمدير.
- كل الردود `no-store`؛ أخطاء المزوّد الخام لا تُعاد للمستخدم ولا تسجّل. معلومات التدقيق وصفية فقط دون التسجيل أو التفريغ.
- قوائم الاتصال والردود ومنع تكرار النطق مؤقتة في ذاكرة عملية واحدة. للنشر متعدد النسخ يلزم مخزن مشترك وتنسيق للحصص والجلسات؛ لا يوجد ضمان exactly-once أو إغلاق عن بُعد بعد تعطل العملية.
- تم إيقاف WebSocket القديم غير الموثّق `/api/live-agent` برد `410 Gone`. صفحة المساعد الحي القديمة أصبحت مدخلاً للمساعد الجديد.
- تبقى وحدات الذكاء الاصطناعي المحاسبي القديمة الأخرى مستقلة. هذه الإضافة ليست مراجعة أمنية شاملة لكل مسارات ERP القديمة؛ راجع التطبيق بالكامل قبل النشر العام.

## الاختبارات

```bash
npm run test:operator-assistant
npm run typecheck:operator-assistant
npm run typecheck
npm run test:assistant-setup
npm test
npm run build
npm run build:server
npm run test:server-bundle
```

اختبارات الخادم وReact تستخدم بيانات اختبار ومزوّدين وهميين، وتشمل الصلاحيات والكيانات والموافقة وحدود الصوت وردود النموذج وإشارات الفيديو وإغلاق الاتصال والميكروفون والمسودات القديمة وتحديث حالات React المتعددة وصيغ CSV وتنظيف جلسة المستخدم السابق.

اختبار الفيديو الحقيقي والصوت الحقيقي من النهاية إلى النهاية يتطلب حسابات ومفاتيح وأجهزة صوت وشبكة تسمح بـ WebRTC. يوجد اختبار تشغيل فعلي للخادم المجمّع CJS المستخدم في حزمة Windows، مع تصحيح تهيئة createRequire في هذا المسار. اختبارات Windows المنطقية وتشغيل الخادم المجمّع لا تعني اختبار المثبّت فعلياً على جهاز Windows.

يتوفر الآن فحص شامل عبر `npm run typecheck`، وفحص مخصص لملفات المساعد وتبعياتها. أُصلحت واردات صفحة النماذج الناقصة وأُضيف اعتماد محدد الطلبات المفقود.
